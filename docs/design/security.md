# ローカルの信頼境界

`nnx serve` は信頼された 1 人のユーザーのためのローカルツールであり、認証付きのマルチユーザーサービスではない。
その脅威モデルでは、ネットワークとブラウザを信頼しない。

サーバは既定で loopback にバインドする。
設定の `server.port` はポートだけを持ち、ホストは持たない。auto でも固定でも、待ち受けるのは loopback である。
loopback 以外に公開するには、`nnx serve --addr` で listen アドレスを明示する必要がある。LaunchAgent はこのフラグを渡さないので、常駐サーバが loopback の外に出ることはない。
LaunchAgent の plist と稼働記録はどちらも 0600 で、秘密情報を含まない。
リクエストは設定された origin と RPC プロトコルに束縛しなければならない。別の origin がローカルのデータベースを操作できないようにするためである。

ローカルファイルのプレビューは、明示的に登録された document のパスに限る。
汎用のファイルシステム読み取り手段にしてはならない。
ローカルファイルの読み取りは 1 MiB までとし、内容は妥当な UTF-8 テキストでなければならない。
URL の document を content 読み取り API が取得することはない。

WebUI は、OS のファイル選択ダイアログを開くようローカルサーバに依頼できる。
このダイアログが返すのは選択された絶対パスだけで、ファイルを読むことも登録することもない。
同時に開けるダイアログは 1 つだけである。
キャンセルは正常な結果として扱い、ネイティブのヘルパーが使えない場合も手入力によるパス指定は残る。
この RPC も、他のすべての変更操作と同じ Host・Origin・Connect プロトコルの検査を受ける。

WebUI は、新しいリリースへの更新をローカルサーバに依頼できる。
サーバはそのとき、配布元 GitHub Release に添付された `install.sh` を取得して `bash` で実行する。RPC が外部から取得したコードを実行する唯一の場所であり、信頼境界の意図的な拡張である。
取得元は配布元リポジトリの Release 資産に固定されており、設定でも RPC のリクエストでも変えられない。実行するタグは semver として読める値だけで、配布元の URL に任意の文字列を差し込むことはできない。
取得したスクリプトの検証はスクリプト自身が持つ。チェックサムと版番号を検証してから既存バイナリを置き換え、検証に失敗したときは何も変更しない。詳細は [updates.md](updates.md) にある。
実行は非対話で、上限時間を伴う。開発ビルドと `nnx serve --demo` ではこの RPC 自体が無効である。

本番のレスポンスには制限の強いブラウザ用セキュリティヘッダを付ける。
現在のヘッダ一式とリクエスト検証の仕組みは、サーバの実装が所有する。
